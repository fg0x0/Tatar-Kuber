**Trending, one scan in either language, and two places where the tool was misdescribing itself.**

## Scan trending — `diff`

An audit is not a one-off: you scan, they fix, you scan again. At that point "26 findings" says nothing — 26 unchanged and 20-fixed-plus-20-new look identical in a total.

```bash
tatar-kuber diff --old prev/scan-result.json --new out/scan-result.json
tatar-kuber diff --old prev/scan-result.json --new out/scan-result.json --fail-on-new high   # CI
```

Two scans are compared by the **stable finding ID** (`StableID(control, resource, namespace)`), so the same issue getting worse is reported as *worsened* — not as one finding disappearing and another appearing. New / fixed / worsened / improved / unchanged, with per-severity and score deltas, `-o text|json`, `--lang en|mn`, and `--fail-on-new <severity>` for a CI exit code.

**A falling count is not automatically good news** — a scanner that dies produces the same shape. So `diff` also compares `metadata.scanner_runs`: a scanner that produced findings before and produces none now is flagged **COVERAGE REGRESSED** instead of being read as progress. This is the v1.0.0 failure mode turned into a check.

Comparisons that cannot be trusted — a different cluster, a different mode, or one side scanned with `--no-rollup` (which changes `resource` and therefore every ID) — are reported as warnings rather than silently producing a misleading diff.

## One scan, either language — `report --lang`

Language used to be chosen at *scan* time and baked into `scan-result.json`, so handing the same audit to an English reader and a Mongolian one meant running the scanners twice against the cluster.

```bash
tatar-kuber report --input out/scan-result.json -o html --out en.html
tatar-kuber report --input out/scan-result.json -o html --lang mn --out mn.html
```

It applies to JSON, SARIF and HTML alike, never rewrites the source file — so `metadata.result_hash` stays verifiable — and refuses a language the registry does not carry instead of quietly falling back to English.

## Fixes — the tool was misdescribing itself

- **`scan_mode` was lying.** An offline `--raw-dir` ingest labelled itself `remote`, so a report produced without ever contacting a cluster claimed to be a live cluster scan. For an audit artifact that is a provenance error, and it also blinded `diff`: a live scan and a replayed one both read as `remote`, so the mode-mismatch warning could never fire between them. Offline ingest is now `offline`.
- **Version could drift in two directions.** `metadata.tatar_version` comes from a constant that release tooling cannot inject — only `cli.Version` is set by ldflags. A release could therefore ship a binary reporting one version while writing another into every report and SARIF file. A test now fails when the two disagree.
- **The HTML report declared the wrong language.** `<html lang>` was hardcoded to `mn`, so an English report announced itself as Mongolian to screen readers, translators and indexers.
- **An installer outage no longer sinks the scanner guard.** The live and static workflows run daily instead of weekly; each scanner install retries, and one that still fails is surfaced as `unavailable` while the rest of the scan proceeds.

## Verified before shipping

The published v1.0.2 binary was downloaded and exercised end to end — `scan`, `report`, `gate`, `verify-lab` (Lab regression **PASS**), SARIF 2.1.0 valid. On identical raw input the v1.0.2 binary and this release produce the **same `result_hash`**, so nothing in the analysis core moved.

# Монгол

**Тренд, нэг scan-аас аль ч хэл, мөн хэрэгсэл өөрийгөө буруу тайлбарлаж байсан хоёр газар.**

## Тренд — `diff`

Аудит бол нэг удаагийн ажил биш: шалгана, засна, дахин шалгана. Тэр үед "26 finding" гэсэн тоо юу ч хэлэхгүй — 26 нь хэвээрээ байгаа ч, 20 зассан дээр 20 шинэ гарсан ч нийт тоонд ижил харагдана.

```bash
tatar-kuber diff --old prev/scan-result.json --new out/scan-result.json --lang mn
tatar-kuber diff --old prev/scan-result.json --new out/scan-result.json --fail-on-new high
```

Хоёр scan-ыг **тогтвортой finding ID**-гаар тулгана, тиймээс ижил асуудал дордсоныг *дордсон* гэж хэлнэ — "хуучин нь арилж шинэ нь гарлаа" гэж биш. Шинэ / зассан / дордсон / сайжирсан / хэвээр, severity тус бүрийн ба онооны зөрүүтэй.

**Тоо буурах нь өөрөө сайн мэдээ биш** — scanner унасан ч яг ийм дүр зураг гарна. Тиймээс `metadata.scanner_runs`-ыг мөн тулгана: өмнө finding өгч байсан scanner одоо 0 өгвөл **ХАМРАХ ХҮРЭЭ БУУРСАН** гэж тэмдэглэнэ, "ахиц" гэж уншигдахгүй. Энэ бол v1.0.0-ийн алдааг шалгалт болгож хувиргасан хэрэг.

Итгэх боломжгүй харьцуулалтыг — өөр cluster, өөр горим, эсвэл нэг тал нь `--no-rollup` — чимээгүй өнгөрөөхгүй, анхааруулга болгож гаргана.

## Нэг scan, аль ч хэл — `report --lang`

Хэл нь *scan* хийх үед сонгогдож `scan-result.json` дотор шатдаг байсан тул нэг аудитыг англи уншигч, монгол уншигч хоёрт өгөхийн тулд scanner-уудыг cluster дээр хоёр удаа ажиллуулах хэрэгтэй байв.

```bash
tatar-kuber report --input out/scan-result.json -o html --lang mn --out mn.html
```

JSON, SARIF, HTML гурвуулд үйлчилнэ, эх файлыг хэзээ ч дарж бичихгүй — тиймээс `metadata.result_hash` шалгагдах хэвээр — мөн registry-д байхгүй хэлийг чимээгүй англи руу унагахгүй, шууд татгалзана.

## Засварууд — хэрэгсэл өөрийгөө буруу тайлбарлаж байв

- **`scan_mode` худал хэлж байв.** `--raw-dir` офлайн ingest нь өөрийгөө `remote` гэж тэмдэглэдэг байсан тул cluster руу огт хандаагүй тайлан "амьд кластерын scan" гэж зарладаг байв. Аудитын артефактад энэ бол гарал үүслийн алдаа, мөн `diff`-ийг сохолдог: амьд scan ба дахин тоглуулсан хоёул `remote` тул горим зөрүүгийн анхааруулга тэдний хооронд хэзээ ч хөөрөх боломжгүй байв. Одоо `offline`.
- **Хувилбар хоёр тийш салах боломжтой байв.** `metadata.tatar_version` нь release хэрэгслийн хүрдэггүй const-оос ирдэг — ldflags зөвхөн `cli.Version`-ыг тавьдаг. Тиймээс нэг хувилбар хэлж, тайлан бүр болон SARIF-д өөр хувилбар бичдэг binary гарах боломжтой байв. Одоо хоёр нь зөрвөл тест унана.
- **HTML тайлан хэлээ буруу зарладаг байв.** `<html lang>` нь `mn` гэж хатуу бичээстэй байсан тул англи тайлан өөрийгөө монгол гэж дэлгэц уншигч, орчуулагч, индексжүүлэлтэд танилцуулдаг байв.
- **Суулгагчийн саатал scanner-ийн хамгаалалтыг унагахаа болив.** Амьд ба статик workflow долоо хоног тутмын оронд өдөр бүр ажиллана; суулгалт бүр дахин оролдоно, тэгсэн ч бүтэхгүй scanner нь `unavailable` гэж гарч, үлдсэн scan үргэлжилнэ.

## Гаргахын өмнө шалгав

Нийтлэгдсэн v1.0.2 binary-г татаж бүрэн ажиллуулав — `scan`, `report`, `gate`, `verify-lab` (Lab regression **PASS**), SARIF 2.1.0 хүчинтэй. Ижил түүхий оролт дээр v1.0.2 binary ба энэ release **ижил `result_hash`** өгсөн, өөрөөр хэлбэл шинжилгээний цөм хөдлөөгүй.
