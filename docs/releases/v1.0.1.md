## What was wrong in v1.0.0 (please read)

An audit of v1.0.0's own live run on a real `kind` cluster showed that **all 11 findings came from
Kubescape alone**. Trivy and Popeye were installed, `doctor` reported them as ready, their versions
were recorded in the report — and they contributed **nothing**. Because adapter errors were swallowed
and CI only asserted "total findings ≥ 1", this stayed green.

For a security posture tool, under-reporting is the worst failure mode: it produces a false sense of
safety. **If you ran a live scan with v1.0.0, its coverage was Kubescape-only** — Trivy's image CVEs,
secrets and misconfiguration were entirely missing. Re-run it with v1.0.1.

### Root causes

| Scanner | Cause |
|---|---|
| Trivy | Registry mapped `AVD-KSV0017`, real Trivy emits `AVD-KSV-0017` (hyphenated) — no rule ever matched. `trivy k8s` also defaults to `--report summary`, so detailed results never arrive in the JSON, and kube context is a **positional argument**, not `--context`. |
| Kubescape | Context was never passed at all (the flag is `--kube-contexts`, plural) — a scan of `--context prod` could silently hit a *different* cluster. Fleet mode also renames its own output file (`scan.json` → `scan.<context>.json`). |
| Popeye | 0.22 changed its JSON schema (`sanitizers` → `sections`) **and** the meaning of its POP codes. **7 of the 10 Popeye mappings pointed at the wrong canonical control** — e.g. POP-108 "unnamed port" was reported as "Missing CPU/memory limits", POP-1500 "is suspended" as "Missing NetworkPolicy". |
| Severity | Popeye's lint level (info/warn/error) overrode each control's **curated** `default_severity`: a dead Service was reported HIGH where the registry deliberately rates it INFO, a missing probe MEDIUM instead of LOW — inflating both the report and the risk score. |

The fixtures were part of the problem: their POP messages were **invented** (`[POP-106] No image
tag/digest pinned` — POP-106 actually means "no resources requests/limits"). That self-consistent
data let the wrong mappings pass every test. They now mirror real scanner output.

### Live result on a real cluster

| | v1.0.0 | v1.0.1 |
|---|---|---|
| Trivy | **0** | 323 |
| Kubescape | 11 | 18 |
| Popeye | **0** | 12 |
| Total (after dedup) | 11 | 26 |
| Corroborated by 2+ scanners | **0** | 8 |
| Canonical controls | 6 | 16 |

Cross-scanner deduplication — the project's signature feature — is working across scanners for the
first time.

## So this cannot hide again

- **`metadata.scanner_runs[]`** records every scanner's outcome: status (`ok` / `unavailable` /
  `unsupported` / `error` / `timeout` / `parse_error`), version, duration, findings, and the rules
  that had no canonical mapping. Surfaced in the HTML report as a **Scanner coverage** table — a
  failed or empty scanner is shown, never hidden.
- **Raw scanner output is kept** in `<out>/raw/` as evidence, in the same layout `--raw-dir` accepts,
  so any scan can be re-processed and audited. Disable with `--no-raw`.
- **CI asserts each scanner individually** on a real kind cluster: every available scanner must
  produce findings, Trivy must find the privileged container, and at least one finding must be
  corroborated by 2+ scanners.
- **A test pins every mapped POP code against upstream's `codes.yaml`**, so a scanner renaming or
  renumbering its checks fails the build instead of silently mis-reporting.

## Other fixes

- `gate`: `--fail-on` / `--min-score` now override `.tatar-kuber.yaml` only when explicitly passed —
  previously the default `--min-score 0` always clobbered the policy file's value.
- GitHub Action: `registry` now defaults to the embedded registry (it pointed at
  `schema/canonical-controls.yaml`, which does not exist in a consumer's repo, so the action failed);
  inputs are passed via env to avoid script injection.
- SARIF: a rule's `security-severity` is now the **highest** severity among its findings (it was the
  first one encountered), and `partialFingerprints` was added so GitHub Code Scanning deduplicates
  alerts correctly across scans.
- Finding IDs went from 6 to 12 hex characters (24 → 48 bits): at ~4 000 findings the old length had
  a ~40% collision probability, which would break dedup, SARIF fingerprints and diffs. **IDs change
  once with this release** — Code Scanning will open alerts anew.
- Popeye: kind names are singularized correctly (`ingresses` → `ingress`), and a multi-namespace scan
  no longer silently scans the whole cluster.
- Cleanup: `securego/gosec` pinned (a security tool should not be pulled from `@master`), the unused
  `internal/kube` stub removed, `update` documented honestly as planned for v2, severity ranking
  unified into one source, and the CLI layer now has end-to-end tests (14 → 15 packages).

## Note

`docs/04_Severity-Risk-Scoring-Model.docx` §2 still documents the old Popeye level → severity table
and no longer matches the code. It will be corrected in the next docs pass.

# Монголоор

## v1.0.0-д юу буруу байсан (уншина уу)

v1.0.0-ийн бодит `kind` cluster дээрх live run-ыг аудит хийхэд **11 finding бүгд зөвхөн
Kubescape-ээс** ирсэн нь тогтоогдов. Trivy, Popeye хоёул суусан, `doctor` бэлэн гэж харуулсан,
хувилбар нь тайланд бичигдсэн — гэтэл **юу ч өгөөгүй**. Adapter-ийн алдаа залгигдаж, CI нь зөвхөн
"нийт finding ≥ 1" гэж шалгадаг тул ногоон хэвээр байв.

Аюулгүй байдлын хэрэгсэлд дутуу тайлагнах нь хамгийн хортой алдаа — "цэвэр байна" гэсэн хуурамч
тайвшрал өгдөг. **Хэрэв та v1.0.0-оор live scan хийсэн бол түүний хамрах хүрээ Kubescape-ээр
хязгаарлагдсан** — Trivy-ийн image CVE, secret, misconfiguration бүхэлдээ дутуу. v1.0.1-ээр дахин
ажиллуулна уу.

### Үндсэн шалтгаанууд

| Scanner | Шалтгаан |
|---|---|
| Trivy | Registry-д `AVD-KSV0017`, бодит Trivy `AVD-KSV-0017` (зураастай) гаргадаг — нэг ч rule таараагүй. Мөн `trivy k8s`-ийн default нь `--report summary` тул дэлгэрэнгүй үр дүн JSON-д огт ирдэггүй, kube context нь `--context` flag биш **positional аргумент**. |

| Popeye | 0.22 нь JSON схемээ (`sanitizers` → `sections`) **БОЛОН** POP кодынхоо утгыг сольсон. **Popeye-ийн 10 зураглалын 7 нь буруу canonical control руу зааж байв** — ж: POP-108 "unnamed port"-ыг "Missing CPU/memory limits", POP-1500 "is suspended"-ыг "Missing NetworkPolicy" гэж. |

## Ингэснээр дахин нуугдахгүй

- **`metadata.scanner_runs[]`** нь scanner бүрийн үр дүнг бүртгэнэ: төлөв (`ok` / `unavailable` /
  `unsupported` / `error` / `timeout` / `parse_error`), хувилбар, хугацаа, finding тоо, мөн canonical
  зураглалгүй rule-ууд. HTML тайланд **Scanner хамрах хүрээ** хүснэгтээр харагдана — унасан эсвэл
  хоосон scanner нуугдахгүй.
- **Түүхий scanner гаралтыг** `<out>/raw/` дотор нотолгоо болгон хадгална, `--raw-dir` хүлээж авдаг
  яг тэр бүтцээр — тиймээс scan бүрийг дахин боловсруулж, аудит хийж болно. `--no-raw`-аар болино.
- **CI нь scanner тус бүрийг** бодит kind cluster дээр шалгана: суусан scanner бүр finding өгөх ёстой,
  Trivy privileged контейнерийг олох ёстой, ядаж нэг finding 2+ scanner-ээр батлагдсан байх ёстой.
- **Зураглагдсан POP код бүрийг upstream-ийн `codes.yaml`-тай тулгах тест** — scanner шалгалтаа
  дахин нэрлэх/дугаарлахад чимээгүй буруу тайлагнахын оронд build унана.

## Бусад засвар

- `gate`: `--fail-on` / `--min-score` нь одоо зөвхөн тодорхой өгсөн үед `.tatar-kuber.yaml`-ыг дарна —
  өмнө нь default `--min-score 0` бодлогын файлын утгыг үргэлж дардаг байв.
- GitHub Action: `registry` default нь одоо шигтгэсэн registry (өмнө нь хэрэглэгчийн repo-д байдаггүй
  `schema/canonical-controls.yaml` руу заадаг тул action унадаг байв); оролтуудыг env-ээр дамжуулж
  script injection-оос сэргийлэв.
- SARIF: rule-ийн `security-severity` нь одоо түүний finding-үүдийн **хамгийн өндөр** severity
  (өмнө нь эхэлж таарсны severity), мөн `partialFingerprints` нэмэгдсэн тул GitHub Code Scanning
  scan хооронд alert-ыг зөв дедуп хийнэ.
- Finding ID 6-аас 12 hex болов (24 → 48 бит): ~4 000 finding-тэй үед хуучин урт нь ~40% магадлалаар
  мөргөлддөг байсан нь dedup, SARIF fingerprint, diff-ыг эвднэ. **Энэ release-д ID нэг удаа
  солигдоно** — Code Scanning alert-ууд шинээр үүснэ.
- Popeye: kind нэрийг зөв ганц тоо болгоно (`ingresses` → `ingress`), олон namespace-тэй scan нь
  бүх cluster-ыг чимээгүй шалгахаа болив.
- Цэвэрлэгээ: `securego/gosec` pin хийгдсэн (аюулгүй байдлын хэрэгслийг `@master`-аас татах ёсгүй),
  хэрэглэгдээгүй `internal/kube` stub устгасан, `update` командыг v2-т төлөвлөсөн гэж шударгаар
  тэмдэглэсэн, severity эрэмбийг нэг эх сурвалж болгосон, CLI давхаргад E2E тест нэмсэн (14 → 15 багц).
